# Architecture

A bird's-eye view of how this repository is put together. For "how do I fix
or add a scraper" task instructions, see [AGENTS.md](../AGENTS.md) instead —
that document is kept in sync with the code by the test suite (via
`docs/scraper_template.py` and `tests/test_template.py`); this one is prose
and can drift, so where the two disagree, trust AGENTS.md and the code.

## What this repository is

A library of ~40 per-council scrapers that each turn one council's meetings
page into a list of structured `ScraperReturn` records (name, date, time,
agenda/minutes URLs, location). `aus_council_scrapers/main.py` is the one
entry point that runs them and does something with the output — either clean
JSON to stdout (**adapter mode**, what production uses) or a local pipeline
of SQLite storage, PDF keyword extraction, and email/Discord notifications
(**legacy mode**, still functional, not run on a schedule by anything in
this repo). See the [README](../README.md) for how to run either.

This repository does not itself serve or store "the data" anywhere
persistent for end users. The [council-alerts](https://github.com/yimbymelbourne/council-alerts)
repository is what runs adapter mode nightly and owns the durable database —
this repo is the scraping engine it calls, not the place the scraped data
lives long-term.

## Package layout

```
aus_council_scrapers/
  main.py            CLI entry point — the only place that ties a scraper's
                      output to a destination (stdout JSON / SQLite+PDFs+
                      notifications)
  base.py             BaseScraper, ScraperReturn, Fetcher/DefaultFetcher,
                      InfoCouncilScraper, the @register_scraper decorator
                      and SCRAPER_REGISTRY
  platforms.py        Signature-based detection of known meeting-publishing
                      platforms, used by scripts/detect_platform.py
  conformance.py      What a scraper's recorded fixture is judged against —
                      invariants (fail the build) vs coverage (reported only)
  constants.py        EARLIEST_YEAR, shared regexes, per-state timezones,
                      IDENTIFYING_USER_AGENT
  clock.py            today() / current_year() — routes through a freezable
                      clock so replay isn't tied to the real calendar
  database.py         SQLite persistence for legacy mode (agendas.db)
  discord_bot.py      Discord notification client for legacy mode
  logging_config.py   Logging setup shared by main.py
  utils.py            PDF download/text-extraction, keyword extraction,
                      email composition/sending — all legacy-mode support
  scrapers/
    <state>/          One package per state (vic, nsw, qld, act);
                       <council>.py per council, imported by the state's
                       own __init__.py — see "The import chain" below
docs/
  councils.md          Hand-maintained: every tracked council, its meeting
                       page URL, and its slug
  status.md            Generated by scripts/scorecard.py — which councils
                       are complete/partial/broken, derived from fixtures
  scraper_template.py  Starting point for a new scraper; kept valid by
                       tests/test_template.py
  discord.md           Discord bot setup walkthrough (legacy mode)
  architecture.md      This file
scripts/
  detect_platform.py   Identify a council's platform before writing a parser
  scorecard.py          Coverage report derived from the fixtures
  migrate_database.py   One-shot schema upgrade for a pre-existing agendas.db
tests/
  scraper_test.py       Runs every registered scraper against its cassette
                        (replay if one exists, live-record if not)
  cassette.py           The record/replay machinery (see "Testing" below)
  conformance.py         (referenced from aus_council_scrapers/conformance.py)
  known_broken.py       Strict xfails for scrapers with a known, named defect
  test-cases/            One `<slug>-result.json` (expected output, readable)
                        and `<slug>-replay_data.json.gz` (recorded HTTP
                        responses, gzip-compressed) per registered scraper
```

## Core abstractions

**`ScraperReturn`** — the record every scraper produces one of per meeting.
`name` is optional; `date` and `webpage_url` are required; at least one of
`agenda_url`/`minutes_url`/`download_url` (deprecated but still required for
backward compatibility) must be set. `check_required_properties()` enforces
this and is called by `main.py` right after a scraper runs, so a malformed
record fails loudly at the source rather than downstream.

**`BaseScraper`** — the ABC every scraper extends. Holds `council_name`,
`state`, `base_url`, a per-scraper `logger`, and a `fetcher`
(`DefaultFetcher` by default). Subclasses implement `scraper() -> list[ScraperReturn]`.
An optional `user_agent` constructor param overrides the fetcher's UA for
that instance only — see "The User-Agent question" below.

**`Fetcher` / `DefaultFetcher`** — the HTTP/Selenium abstraction every
scraper goes through instead of calling `requests`/`selenium` directly. This
indirection is what makes record/replay possible: `RecordingFetcher` and
`PlaybackFetcher` (in `tests/cassette.py`) both implement the same interface
and get swapped in during tests. `DefaultFetcher` throttles per host, retries
retryable HTTP statuses (429/500/502/503/504) and connection-level failures
(`ConnectionError`/`Timeout`) with backoff, and raises `BlockedByWAF` — not a
generic error — on a 403, specifically so it reads as a deferral rather than
something to work around locally (see "The User-Agent question").

**`@register_scraper` / `SCRAPER_REGISTRY`** — decorating a `BaseScraper`
subclass instantiates it once and adds it to the module-level
`SCRAPER_REGISTRY` dict, keyed by class name. `main.py` and
`tests/scraper_test.py` both just iterate this registry — neither has a
hardcoded council list. This is also the repo's single sharpest footgun: the
decorator only runs if the module is ever imported, and nothing imports a
scraper module automatically. See "The import chain" immediately below.

**`InfoCouncilScraper`** — a `BaseScraper` subclass handling the InfoCouncil
platform generically (both its legacy `grdMenu`/`bpsGridPDFLink` template and
the newer responsive `div.meeting-row` template). A council confirmed to run
InfoCouncil is usually a ~10-line subclass — see any of
`aus_council_scrapers/scrapers/qld/{redland,ipswich,sunshine_coast,scenic_rim,lockyer_valley}.py`.

## The import chain (read this before adding a scraper)

```
<council>.py  --@register_scraper-->  SCRAPER_REGISTRY
     ^
     | must be imported by
<state>/__init__.py
     ^
     | must be imported by
aus_council_scrapers/scrapers/__init__.py
```

Both arrows are load-bearing and silent when missing — a scraper that's
written, decorated, and never imported simply never runs and never appears
in any test failure, because nothing calls it. AGENTS.md notes nine
historical scrapers lost to exactly this. `aus_council_scrapers/scrapers/act/`
currently exists as an empty placeholder package, imported by nothing —
harmless as-is, but the first ACT scraper added there will need
`scrapers/act/__init__.py` to import it *and* `scrapers/__init__.py` to
import `scrapers.act`, the same two-step every other state needs.

## Platform detection

`aus_council_scrapers/platforms.py` holds regex signatures for meeting
platforms seen across councils (InfoCouncil, docspublished, OpenCities,
Granicus/Legistar, Civica) plus guidance on which base class or reference
scraper to start from. `scripts/detect_platform.py <slug-or-url>` fetches a
page through the project's own throttled fetcher and reports which
signature, if any, matched — the first step before writing a parser by
hand, per AGENTS.md's Step 3.

Not every platform match gets a shared base class. The QLD scrapers on
OpenCities' *listing* widget (as opposed to Strathfield/Banyule's
AJAX-driven one) share `aus_council_scrapers/scrapers/qld/_opencities_paging.py`
(pagination) and `_opencities_detail.py` (per-meeting field/document
parsing) directly between `moreton_bay.py` and `gold_coast.py`, without a
formal base class — a middle ground between "write it from scratch" and
"there's a base class for this," worth reusing if a third council turns out
to run the same widget.

## The User-Agent question (issue #142)

`DefaultFetcher`'s default headers spoof a browser User-Agent. Roughly a
dozen councils' WAFs block that spoofed UA specifically and return 200 for
an honest, identifying one instead — measured, not assumed (see issue
[#142](https://github.com/yimbymelbourne/council-meeting-agenda-scraper/issues/142)).
Whether to change the *default* UA project-wide is a deliberately open,
undecided policy question, not something to resolve unilaterally per
scraper.

What exists today is a narrower, opt-in escape hatch: `constants.IDENTIFYING_USER_AGENT`
plus an optional `user_agent` param on `BaseScraper`/`DefaultFetcher` (mirrors
how `fetch_delay` is already overridable per instance). A scraper only sets
it once the spoofed-UA block is confirmed directly against that council's own
domain — `brisbane.py`, `moreton_bay.py`, and `somerset.py` currently do.
Every other scraper is unaffected; the shared default has not changed.

If a council returns 403 and hasn't been confirmed either way, the correct
response is to stop and say so (`BlockedByWAF`'s own message says as much) —
not to add headers, proxies, or Selenium to push through it.

## Testing: record/replay

Every scraper test runs against a **cassette** — a recorded sequence of
`(request, response)` pairs stored as `tests/test-cases/<slug>-replay_data.json.gz`,
alongside the exact expected output in `<slug>-result.json`. `tests/cassette.py`
defines the format (documented in its own module docstring) and two
`Fetcher` implementations: `RecordingFetcher` (wraps a live fetcher, records
every response it sees) and `PlaybackFetcher` (serves only what was
recorded).

Replay is **strict**: a request the scraper makes that wasn't in the
recording raises `CassetteMiss` rather than a plausible-looking empty page.
That's deliberate — the alternative (silently returning nothing) is how a
scraper regression turns into a quietly shrinking result set instead of a
failing test.

Cassettes are gzip-compressed on disk (`save_replay_data`/`load_replay_data`
in `cassette.py`) because a recorded page is mostly repeated boilerplate
(nav chrome, embedded analytics JSON) even when no two pages are
byte-identical — compression runs 70-90%+ smaller in practice on the
cassettes checked so far, which matters once a council needs a few hundred
individual page fetches to cover (Gold Coast's cassette alone was ~97MB
uncompressed). The in-memory format and strict-replay semantics are
unaffected — only what hits disk changed.

`aus_council_scrapers/conformance.py` is what a recorded fixture is judged
against, in two categories that are deliberately treated differently:

- **Invariants** (`tests/test_conformance.py`) — a meeting emitted twice, an
  unparseable date, a relative URL, zero meetings. These fail the build,
  unconditionally, however new or unfinished a scraper is.
- **Coverage** — meetings found, years spanned, whether minutes are present.
  Reported (`scripts/scorecard.py`, `docs/status.md`) but never gates CI. How
  far back a scraper's history reaches is usually the council's own
  publishing choice, not something the scraper controls, so it isn't scored
  as pass/fail.

A scraper with a known, named defect goes in `tests/known_broken.py` instead
of being silently tolerated — those are *strict* xfails, so a fix that
starts passing fails the build until the entry is removed, which is the
point: debt recorded there can't quietly outlive the fix.

## Known gaps

- **`aus_council_scrapers/scrapers/act/`** is an empty placeholder, imported
  by nothing. Not a bug — just unstarted.
- **Issue #142** (above) is an open policy question, not a bug to fix.
- **`docs/national_councils_dump.txt`** is a raw data dump with no header
  explaining its provenance or schema (added in a single commit titled only
  "Create national_councils_dump.txt"). Kept rather than deleted — its
  purpose isn't obvious from the content alone, which is exactly the
  situation where guessing and deleting would be the wrong call — but it
  would benefit from someone who knows its origin adding a one-line header.
